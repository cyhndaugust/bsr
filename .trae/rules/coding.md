# Rust 编码与学习规范

作为初学者，本项目的目标是：在实现功能的同时，通过高质量的代码实践深入理解 Rust 的核心概念（所有权、借用、生命周期等），并确保代码符合生产级标准和高性能要求。

## 1. 生产级质量保证
- **强类型与安全性**：充分利用 Rust 的类型系统，避免使用 `unsafe`。
- **错误处理**：
  - 禁止使用 `unwrap()` 或 `expect()`，除非在测试代码中或能百分之百确定不会 panic 的场景。
  - 使用 `Result<T, E>` 进行显式错误处理，推荐结合 `anyhow` 或 `thiserror` 库。
- **文档与注释**：
  - 公有函数和类型必须编写文档注释 `///`。
  - 复杂的算法逻辑需辅以详细的代码内注释 `//`。

## 2. Rust 标准规范 (Idiomatic Rust)
- **代码风格**：严格遵守 `cargo fmt`。
- **Lint 检查**：必须通过 `cargo clippy` 的默认检查，严禁忽视警告。
- **所有权与借用**：
  - 优先传递引用 `&T` 而不是转移所有权，除非确实需要拥有数据。
  - 避免不必要的 `.clone()`，优先考虑如何通过架构设计减少内存拷贝。
- **模式匹配**：优先使用 `match` 和 `if let` 来处理 `Option` 和 `Result`。

## 3. 性能优化指南
- **零成本抽象**：利用泛型和 Trait 实现零成本抽象。
- **内存布局**：理解 `Stack` 与 `Heap` 的分配。在高性能路径中，尽量减少堆内存分配。
- **集合使用**：根据场景选择合适的集合（如 `Vec`, `HashMap`, `BTreeMap`），并预先使用 `with_capacity` 预分配空间。
- **迭代器**：优先使用迭代器（Iterators）而非显式 `for` 循环，利用迭代器的惰性求值和编译器优化。

## 4. 教学式开发建议
- **原理讲解**：在修改代码时，请解释为什么要这么改（例如：为了避免二次借用、为了符合借用检查器要求等）。
- **对比学习**：如果当前写法不符合 Rust 惯用法（Idiomatic），请展示推荐的写法并对比优劣。
- **概念引导**：针对初学者容易困惑的概念（如 `String` vs `&str`，`into()` vs `from()`），在相关代码处提供简短解释。

## 5. 持续集成与验证
- **测试先行**：新功能需配有单元测试 `mod tests`。
- **运行验证**：所有更改后必须运行 `cargo check` 确保通过编译。
